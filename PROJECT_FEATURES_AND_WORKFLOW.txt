Soil Health Optimizer (SOIL.AI) - Comprehensive Features and Workflow
======================================================================

1. Project Overview
-------------------
- **Purpose:** Predict soil fertility using machine learning from 12 chemical parameters and provide actionable, science-based recommendations for soil health improvement, maintenance, or preservation.
- **Audience:** Farmers, agronomists, gardeners, agricultural researchers, and students in precision agriculture.
- **Delivery Platform:** React Native mobile application (Android & iOS) with a Flask REST API backend.

2. Dataset
----------
- **Source:** CSV file (`dataset1.csv`) containing 880 soil samples collected from agricultural fields.
- **Features:** 12 chemical parameters:
  - **Macronutrients:** Nitrogen (N), Phosphorus (P), Potassium (K)
  - **Soil Properties:** pH, Electrical Conductivity (EC), Organic Carbon (OC)
  - **Micronutrients:** Sulfur (S), Zinc (Zn), Iron (Fe), Copper (Cu), Manganese (Mn), Boron (B)
- **Target Variable:** Fertility class (Output column, mapped to 0, 1, 2)
- **Class Distribution:**
  - 0 = Less Fertile
  - 1 = Fertile
  - 2 = Highly Fertile
- **Feature Ranges (derived from dataset + agricultural standards):**

  | Parameter | Min | Max | Unit | Typical Range |
  |-----------|-----|-----|------|---------------|
  | N  | 1   | 500 | mg/kg | 6-383 |
  | P  | 0.1 | 150 | mg/kg | 3-125 |
  | K  | 5   | 1000| mg/kg | 11-887 |
  | pH | 0.5 | 14  | —     | 0.9-11.2 |
  | EC | 0.05| 3   | dS/m  | 0.1-0.95 |
  | OC | 0.05| 30  | %     | 0.1-24 |
  | S  | 0.5 | 50  | mg/kg | 0.6-31 |
  | Zn | 0.05| 50  | mg/kg | 0.07-42 |
  | Fe | 0.1 | 50  | mg/kg | 0.21-44 |
  | Cu | 0.05| 5   | mg/kg | 0.09-3 |
  | Mn | 0.1 | 40  | mg/kg | 0.11-31 |
  | B  | 0.05| 5   | mg/kg | 0.06-2.8 |

3. Model Training Pipeline (Offline)
-------------------------------------
- **Environment:** Jupyter Notebook (`soil-fertility-prediction.ipynb`)
- **Library:** scikit-learn 1.3.0, Pandas 2.1.0, NumPy 1.25.2
- **Preprocessing:** Log10 transformation applied to all numeric features (handles right-skewed distributions). A small constant (1e-10) is added before log to avoid log(0) errors.
- **Train/Test Split:** 80% training, 20% testing, with shuffling and random_state=42 for reproducibility.
- **Algorithms Evaluated (5 classifiers):**
  1. Random Forest Classifier (n_estimators=100, random_state=42)
  2. Support Vector Machine (SVM)
  3. K-Nearest Neighbors (KNN)
  4. Naive Bayes
  5. Decision Tree Classifier
- **Evaluation Metrics:** Accuracy, confusion matrix, classification report (precision, recall, F1-score)
- **Best Model:** Random Forest Classifier — selected for highest accuracy and robustness against overfitting.
- **Model Serialization:** Trained model saved as `model/random_forest_model.pkl` using Python's pickle module. Also transpiled to JavaScript via m2cgen library for on-device mobile inference.

4. Backend API (Flask)
----------------------
- **Framework:** Flask 2.3.3 with Flask-CORS for cross-origin support
- **Endpoints:**

  | Endpoint | Method | Purpose |
  |----------|--------|---------|
  | `/` | GET | Serves the API root (optional health check landing) |
  | `/api/health` | GET | Health check — returns `{"status": "online"}` |
  | `/api/predict` | POST | Main prediction endpoint — accepts JSON, returns JSON |

- **Prediction Flow (API):**
  1. Receive JSON payload with 12 soil parameters
  2. Validate each parameter against realistic ranges (type check, range check)
  3. Return HTTP 400 with descriptive error if validation fails
  4. Convert input to DataFrame with exact column order matching training
  5. Apply log10 transformation (same as training pipeline)
  6. Load pickled Random Forest model
  7. Call `model.predict(transformed_input)` to get class (0/1/2)
  8. Map class to fertility label and retrieve corresponding recommendations
  9. Return JSON response with prediction, label, confidence score, recommendations, input echo, and timestamp

- **API Request Example:**
  ```
  POST /api/predict
  Content-Type: application/json

  {
    "N": 100, "P": 15, "K": 200, "pH": 6.5, "EC": 0.5, "OC": 1.0,
    "S": 15, "Zn": 1.0, "Fe": 7.0, "Cu": 0.5, "Mn": 3.0, "B": 1.0
  }
  ```

- **API Response Example:**
  ```json
  {
    "success": true,
    "prediction": 2,
    "fertility_class": "Highly Fertile",
    "confidence_score": 0.85,
    "recommendation": {
      "title": "Soil Preservation Plan for Highly Fertile Soil",
      "description": "Your soil is highly fertile...",
      "actions": [
        "Practice precision nutrient management...",
        "Maximize continuous living roots...",
        "Implement diverse crop rotations...",
        ...
      ]
    },
    "input_data": { "N": 100, "P": 15, ... },
    "timestamp": "2025-06-15 14:30:00"
  }
  ```

5. Recommendation System
------------------------
- **Source Guidelines:** USDA Natural Resources Conservation Service (NRCS) and Food and Agriculture Organization (FAO) standards.
- **Three Recommendation Sets:**

  | Class | Plan Type | Focus |
  |-------|-----------|-------|
  | Less Fertile (0) | Soil Improvement Plan | Restoration: minimize tillage, cover crops, biodiversity, organic amendments, pH correction, targeted fertilization |
  | Fertile (1) | Soil Maintenance Plan | Sustenance: crop rotation, conservation tillage, strategic cover crops, nutrient budgeting |
  | Highly Fertile (2) | Soil Preservation Plan | Preservation: precision nutrient management, no-till, agroforestry, continuous living roots |

### 6.4 On-Device Inference
- **Method:** m2cgen transpilation — the trained Random Forest model is converted to pure JavaScript via `convert_model.py`
- **File:** `src/utils/ModelInference.js` (28,132 lines of transpiled decision tree logic)
- **Process:** Input values are log-transformed → passed to the predict() function → returns probability array [p0, p1, p2] → argmax gives class → class mapped to label + recommendation
- **Latency:** Approximately 100ms per inference on modern devices
- **Advantage:** Fully offline operation — no network connectivity required

7. Data Management
------------------
- **No Database:** All operations are stateless. No user data, prediction history, or session data is persisted.
- **File-Based Storage:**
  - `data/dataset1.csv` — Training dataset (880 samples)
  - `model/random_forest_model.pkl` — Serialized trained model
  - `mobile-app/src/utils/ModelInference.js` — Transpiled JavaScript model for mobile

8. Model Conversion Pipeline
-----------------------------
1. Train model in Jupyter Notebook (`soil-fertility-prediction.ipynb`)
2. Save as pickle: `extract_model.py` loads CSV, preprocesses, trains RF, saves to `model/random_forest_model.pkl`
3. Convert for mobile: `convert_model.py` loads pickle, transpiles to JS via m2cgen, writes to `mobile-app/src/utils/ModelInference.js`
4. Mobile app imports predict() function and uses it directly for on-device inference

9. Security & Best Practices
-----------------------------
- **Input Validation:** Every parameter is checked against realistic ranges on both the mobile app (Alert popup) and backend API (HTTP 400 error)
- **Error Handling:** Structured try/catch with logging; user-friendly error messages on mobile (Alert) and API (JSON error response)
- **No Sensitive Data:** No authentication, no database, no user data storage
- **CORS:** Enabled on backend for cross-origin API access
- **Logging:** Flask backend uses RotatingFileHandler with log rotation (10KB per file, 10 backups)

10. Extensibility
-----------------
- **New Parameters:** Add input fields in PredictionScreen + backend validation
- **Persistent Storage:** Add SQLite or PostgreSQL to track predictions over time
- **API Integration:** External services can call /api/predict for automated soil analysis
- **TensorFlow Lite:** Replace m2cgen with TFLite for hardware-accelerated on-device inference
- **Additional Models:** Support multiple crop-specific models selected by user
